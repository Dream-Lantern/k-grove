# 技术图表设计

读取用户指定的正文、现有图源与参考图片，先梳理实体、动作、条件、状态和转换，再决定布局。参考图提供视觉方向，不能覆盖正文和图源中的技术边界；有冲突时说明差异，不默默改写技术结论。

## 工具与交付选择

- 精确中文、参数、代码和复杂流程优先使用原生 SVG：文本可选中、节点和连线可编辑，使用 `viewBox`，不要把文字转成路径。HTML/CSS 可用于布局与预览；最终 SVG 尽量使用标准 SVG 元素，避免依赖 `foreignObject`、外部字体、远程资源或脚本。
- 简单时序图或短流程可复用项目现有 Mermaid + CLI。复杂流程不强制塞进 Mermaid。ImageGen 适合教学插画和视觉创意，不用它绘制需要逐字准确的中文技术图。
- 优先复用现有渲染工具与浏览器。只有确有需要才添加依赖；采用浏览器工具时遵循当前环境的浏览器 Skill，不假设特定接口永远可用。
- 将 SVG 保存到目标文章的图片目录；需要预览时同目录生成 PNG。SVG 自身可作为图源，复杂图可补充小型生成脚本或结构描述，避免维护两份互相矛盾的流程。

## 视觉与阅读

白色或浅色画布，优先横向文档布局；16:9 是参考而非硬性尺寸。节点多时拆为主流程与局部细节，不靠缩小字号塞满画布。使用圆角卡片、细边框、柔和色块、适度留白和编号；节点只保留标题和简短说明，详细条件放正文或局部图。

默认色彩语义：蓝色主流程（`#2563EB`）、紫色判断（`#7C3AED`）、绿色成功（`#059669`）、橙色等待（`#D97706`）、红色失败或拒绝（`#DC2626`）。使用相应低饱和背景，文字用深色，不依赖颜色单独区分状态；判断、分支和退出必须有文字标签。若项目已有规范，协调色值但保留语义。

连线先规划再排节点，采用明确箭头和分支标签，优先正交或短曲线，给回路保留外侧通道，减少交叉。小图标只是辅助，不能替代节点含义。在实际文章宽度下检查中文字号；手机端可保留可放大原图入口，不能声称缩到手机宽度仍可逐字阅读大型架构图。

## 语义约束

生成前记录关键节点与边，包含失败、拒绝、等待、预算耗尽、重试和结束验证等正文实际存在的路径。不虚构分支；不能把“请求工具”画成“已执行工具”，把“等待”画成“成功结束”，或把拒绝路径接入成功输出。

保留来源/版本以及已实现、建议设计、未验证之间的区分。拆图时用对应节点名和正文解释覆盖重要状态及转换；不能仅为避免交叉删边。遇到技术冲突先标出待确认项，图内保留确定程度。

## 渲染验收与修改边界

实际渲染 SVG 并打开渲染结果查看，不能只检查 XML 或截图文件是否存在。核对中文、换行、节点边界、箭头端点、分支标签、遮挡和交叉；再逐条对照结构描述与正文。

更新目标 Markdown 的图片引用和必要图注，保留原图源以便比较。用 VitePress 本地页面确认图片加载、文档宽度、移动端缩放入口及深色模式周围的对比度，运行相关构建/链接检查。图内用浅色背景时可在深色页面保留浅色画布，不强制反色。

未完成实际渲染或网页验收时如实标明。交付 SVG/可选 PNG、图源位置、语义改动与验证结果；先交一张样例等待风格确认，再开展批量工作。
