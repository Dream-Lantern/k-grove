# 技术笔记整理

输入为用户明确选定的笔记、目标分类词表，以及独立私有工作区的位置。仅处理授权范围；没有选定输入时不要扫描现有私有笔记库。

## 输出与边界

- 原文只读。先保留原始备份，输出候选稿和整理报告，不删除、移动或覆盖原文。
- 实际笔记的 UID、原始路径、SHA-256、重复映射和审核记录放在独立私有工作区，不能写进公开博客目录。合成验收材料可在本地临时目录测试。
- 不把 draft、ready、文件名中的“发布版”或 AI 判断当作公开许可。只整理候选，不执行发布或改变公开白名单。

## 整理判断

读取目标项目已有的内容规范与受控词表；复用主要领域和分册标识，不凭单个关键词新增分类。每篇建议一个主要领域，可有多个标签；专题、项目只关联单份正文。

先用原始文件哈希识别完全相同文件；再用正文规范化哈希和段落相似性提出候选。规范化只能用于比较，不回写原文。标题相同不等于重复；版本、适用条件、代码和结论不同时应保留差异或建立交叉引用。

合并建议列出保留段落、冲突段落、附件和每段来源。冲突结论不自动取舍；缺图、缺代码、表格丢失及引用不明都标为待处理。不得从无法解析的附件臆造内容。

## 交付

根据任务规模输出简短报告或私有清单，包含：原始来源与哈希、建议 ID/slug、主要分类与标签、重复候选及依据、合并建议、版本冲突、缺失资源、敏感内容与引用授权待审项。网站 ID 不使用历史 UID。

只对用户已授权的候选稿进行可追溯改写；若要求落地合并，另存新稿并附变更说明。将无法判断的项目留待人工决定，不扩大任务为全库迁移。
