# 技术准确性与版本审核

输入为选定文章、声明的软件版本及已有参考资料。先明确审核范围；实际笔记与内部项目材料仅在授权的独立私有工作区处理，不扫描其他笔记或上传内部实现。

## 核心判断

- 区分公开事实、个人可复现实验、推断、未经授权的内部实现。公司经历不能推导出公开权限，不能补写公司架构、指标或成果。
- 用官方文档、版本化源码、发布说明和原始论文复核。版本敏感的说法查询对应版本；访问不到来源时明确记为未验证，不用最新文档反向证明旧版本行为。
- 每个重要结论记录文章位置、适用版本/平台、证据链接及版本定位、核查日期、判断依据。状态用“有证据支持 / 条件不足 / 与证据冲突 / 未验证”，避免把模型置信度当作证明。
- 参数检查默认值、单位、范围、依赖、废弃和实际作用；示例区分伪代码与可运行代码。只在获准的本地环境执行必要实验，不启动生产负载。
- 性能结论检查硬件、软件、模型、精度、负载、并发、输入/输出长度、预热、采样方法与指标定义。不同 TTFT、TPOT、ITL 或吞吐口径不能直接比较；缺条件时要求补证，不编造结果。

## 交付

按影响列出发现：原句或位置、问题、版本条件、证据、建议更正、验证办法。没有证据的术语解释不升级为已确认事实。

默认给更正建议；用户授权修改时保留可审阅差异，并解释技术结论变化。不能静默改结论、补实验数据或删除矛盾证据。

实际来源 UID、内部路径、原始哈希和审校记录留在私有报告中，不加入公开 Frontmatter。事实审核通过不等于敏感内容、转载授权或公开发布审核通过；不自动改 draft 或公开白名单。
