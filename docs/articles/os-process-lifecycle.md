# 第四章 进程状态、fork、exec 与退出

> 阅读标签：现代Linux/POSIX进程接口。

PCB 描述任务的运行与资源信息，但进程不只是“保存寄存器的一个结构体”，还涉及地址空间、文件引用、身份、信号与生命周期；切换 PC 也只是执行流切换的一部分。

## 1. Ready、Running 与 Waiting

![就绪、运行和等待之间的关系](/assets/notes/operating-systems/os-process.svg)

Ready 表示具备运行条件，等待调度；Running 表示当前在某 CPU 上执行；Waiting 表示等待事件。事件完成通常先使任务重新可运行，不保证立刻执行。

这些是教学状态，Linux 的 TASK_RUNNING 可以覆盖正在执行与可运行的含义；不能只凭名称推导每个内核状态都和图中一一对应。停止、僵尸、退出与创建等状态还需另外考虑。

## 2. fork 返回两次，不是代码从头执行两遍

fork 创建子进程，父子从调用返回处继续，父进程得到子 PID，子进程得到 0，失败则按 API 返回错误。子进程不是重新运行 main 的一个普通函数调用。

常规私有内存的逻辑视图相互独立，底层可通过写时复制暂时共享物理页。原笔记“父子共用同一个用户栈”如果不说明这种层次，会误导为父子可任意覆盖同一份可变私有栈。[fork(2)](https://man7.org/linux/man-pages/man2/fork.2.html)

### 现代多线程进程的特殊边界

多线程进程调用fork后，子进程只有调用fork的线程，不是父进程所有线程一起继续。地址空间却可能复制着其他线程持有的互斥量状态。

纸面反例：父进程T2持锁L，T1调用fork；子进程仅有T1，L却仍可能显示为已锁。子T1再等待L，不能指望已不存在于子进程的T2释放它。fork到exec之间须遵守异步信号安全函数限制；pthread_atfork等机制也不使任意第三方库对象自动安全。

因此启动带后台线程的客户端库后，不应假定fork出的子进程可直接复用原客户端实例。该限制是现代Linux/POSIX情景，与Linux 0.11历史fork另行讨论。[fork(2) 多线程注意事项](https://man7.org/linux/man-pages/man2/fork.2.html)

## 3. 文件状态可能仍共享

fork 后对应文件描述符可以引用同一个打开文件描述，因此共享适用的文件偏移与状态标志。进程私有内存独立，不表示所有内核资源都立即复制成独立对象。

例如，父子进程通过继承的同一文件引用顺序读取时，可能相互推进共享偏移。如果业务要求各自从头读取，就应明确打开与偏移策略，不能仅凭“两个 PID”判断资源彼此独立。

## 4. exec 替换当前进程映像

exec 系列成功后不返回原程序继续执行，而是在同一进程身份下装入新的程序映像。它与 fork 的分工不同：前者换程序，后者产生新进程。哪些文件描述符会保留，受 close-on-exec 等规则约束。

shell 常采用“创建子进程，再在子进程 exec”的路径，但不同 shell、内建命令和优化的实现可能不同。这条教学流程并不是每个命令都必经的唯一源码调用栈。

## 5. 退出、等待与僵尸

进程退出后，一些资源被释放，父进程仍需通过等待接口取得状态；尚未被适用等待回收的退出信息形成僵尸状态。僵尸不是仍在运行、持续占用 CPU 的死循环程序。

学习检查：父进程未 wait、子进程已经退出，哪些信息还保留？父进程先退出又会怎样被接管？实际行为按系统规则确定，不通过强制结束未知进程做实验。
