# 第十六章 TLB、地址空间标识与失效

> 阅读标签：通用翻译缓存 / 架构相关失效。

TLB 缓存地址翻译及相关属性，而非文件内容或普通数据。它可避免每次内存访问都完整遍历页表，但命中、未命中、权限异常和缺页仍需分别理解。

## 1. TLB 命中与页表遍历

![未命中之后不一定缺页](/assets/notes/operating-systems/os-tlb.svg)

TLB 没有相应翻译时，硬件或软件按架构进行页表查找；若页表映射有效，可填充翻译继续访问，不需要操作系统读盘。只有相应存在性、权限或其他条件失败时，才进入适用异常路径。

“TLB 和页表没查到”也不能一概解释成“内存中没有数据”：可能需要零页分配、写时复制，也可能地址根本非法。

## 2. 简化有效访问时间公式

纸面模型：TLB 查找时间 t，内存访问时间 m，n 级页表，命中率 h；假设串行访问、无页表缓存、无数据缓存效果、无缺页和其他开销。

```text
命中：t + m
未命中且映射有效：t + (n + 1) × m
平均：h × (t + m) + (1 - h) × [t + (n + 1) × m]
```

原笔记未命中项缺少最终访问数据的那一次，若 n 表示页表级数，就少算一个 m。现实硬件可重叠、缓存页表项或采用其他优化，本式不是实际 CPU 周期预测器。

## 3. 切换地址空间为什么要区分缓存身份？

不同进程同一个虚拟页号可以映射不同物理页框。若使用了错误地址空间的旧翻译，就可能破坏保护与数据正确性。架构可以通过刷新或地址空间标识等机制区分，不能断言每次线程切换都清空全部 TLB。

同进程线程常共享地址空间；进程切换又可能结合 PCID/ASID 等设计减少某些清空。具体条件按 CPU 与内核版本核对，不混用名称。

## 4. 页表更新后为什么需要失效？

修改内存中的页表，并不保证所有 CPU 缓存的旧翻译立即失效。在解除映射、修改权限或复用物理页之前，需要执行相应的失效和跨 CPU 协调，通常称为 TLB shootdown。

因此，从“页表写成只读”到“所有核不再使用旧可写翻译”，还需完成相应协议。源码中的 invalidate 等操作承担正确性职责，不能仅因存在性能开销就随意删除。[Linux 页表概览](https://docs.kernel.org/mm/page_tables.html)

## 5. 优化是多目标权衡

大页可扩大 TLB 覆盖，代价可能包括分配连续性、内存浪费与回收复杂度；访问局部性提高翻译复用，但跨大量页面的访问仍可能受影响。

不要把提高 TLB 命中率简化成“把所有页改得越大越好”。需要固定负载、页尺寸、地址空间与实际硬件，区分 TLB miss、数据缓存 miss、minor/major fault。
