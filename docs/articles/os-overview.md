# 第一章 操作系统全景、历史与学习边界

> 阅读标签：通用原理 / 历史导读。

操作系统在硬件之上提供进程、虚拟地址、文件和通信等抽象，让程序通过统一接口使用计算机资源。多个程序同时运行时，它负责分配 CPU、内存和设备，隔离彼此的访问，并处理运行中的故障。本册从 Linux 0.11 的 CPU 与内存机制入手，再与其他教学系统和现代 Linux 对照。

## 1. CPU、内存与 I/O 的协作 {#_1-三条主线怎样连起来}

假设浏览器、音乐播放器和文本编辑器一起运行。它们都需要 CPU，但不应由某个程序一直独占；浏览器也不应随意读取编辑器尚未保存的文字。三个程序面对的设备各不相同，却都可以通过文件接口读写数据。播放器等待一次磁盘读取时，编辑器仍可能响应键盘。

这些需求引出操作系统的三个核心能力：**资源管理**决定谁在什么时候使用 CPU、内存和设备；**抽象接口**把复杂硬件包装为进程、地址空间和文件等程序容易使用的对象；**隔离与保护**限制程序可以访问的资源，同时允许受控共享。

| 机制     | 解决的问题                       | 基本工作                                           |
| -------- | -------------------------------- | -------------------------------------------------- |
| CPU 调度 | 多个任务都希望运行               | 从可运行任务中选择执行者，保存和恢复必要的执行状态 |
| 内存管理 | 程序需要存储空间，也需要彼此隔离 | 管理内存分配、地址映射和访问权限                   |
| 文件系统 | 应用不应自行解释每种磁盘布局     | 按文件名、文件描述符等接口组织和访问数据           |
| 设备管理 | 各种设备的操作方式不同           | 由驱动程序提交请求、处理完成事件与错误             |
| 同步机制 | 多个执行流可能同时修改共享状态   | 规定访问顺序，避免数据因交错操作而损坏             |

I/O（Input/Output，输入/输出）指计算机与设备之间交换数据。上述机制彼此配合，并不是依次执行一次就结束的流水线；具体调度算法和地址翻译留到后续章节。

### 一次 read() 怎样串起这些机制

以现代 Linux 上读取普通本地文本文件、按空白分隔统计单词为例。假设文件已成功打开，文件描述符为 `fd`，使用普通缓冲 I/O，未采用直接 I/O。文件描述符（File Descriptor）是进程持有的整数句柄，内核通过它找到已打开的文件。

1. 程序准备用户缓冲区，调用 `read(fd, buf, sizeof buf)`。运行库按平台约定发起系统调用，请求进入内核。
2. 内核检查描述符、读取方式、请求长度与用户缓冲区的可访问性，并按文件位置确定要读的数据。非法描述符或访问失败可能使请求以错误返回；文件末尾则可能返回 `0`。
3. 如果数据已在内存中的页缓存（Page Cache）里且可用，可以直接向用户缓冲区复制。若缺少所需数据，文件系统可能通过设备驱动发起读取；这条路径也可能受预读等机制影响。
4. 任务确实需要等待数据时，内核可将它置于等待状态，调度器选择其他可运行任务。设备完成后，驱动更新请求状态并唤醒等待者；**被唤醒表示可以参与调度，不表示立刻占用 CPU**。
5. 原任务再次运行后，内核继续读取、复制并返回实际取得的字节数。程序只处理这些字节；若一个单词跨越两次读取，应保留“上一个字节是否属于单词”的状态，避免重复计数。
6. 程序重复读取，直到返回 `0`，再报告总数；若返回 `-1`，则根据 `errno` 判断重试或报错。读取成功也可能少于缓冲区大小，不能据此直接认定文件结束。

例如文件只含 12 个 ASCII 字节 `red blue\nred`，其中 `\n` 表示一个换行字节。若两次读取分别得到 7 字节 `red blu` 和 5 字节 `e\nred`，计数器初始为 `0`，每次从空白或文件开头进入非空白字符时加一。第一批之后计数为 `2`，并记录“仍在单词中”；第二批开头的 `e` 不再加一，经过换行后遇到 `red` 才加到 `3`。随后读取返回 `0`，程序报告 3 个单词。实际每批长度可以不同，保留跨批状态才能得到相同结果。

这里文件系统定位数据，内存管理支持缓存和用户缓冲区访问，设备管理处理实际 I/O，调度管理等待期间的 CPU 使用。**不是每次 `read()` 都访问物理磁盘，也不是每次都阻塞或切换任务**；即使数据命中缓存，复制时也可能因用户缓冲区缺页等原因等待。此例是机制推演，未在本轮执行。[read(2)](https://man7.org/linux/man-pages/man2/read.2.html) 说明返回值与错误语义；[Linux 6.12 内存概念中的页缓存](https://docs.kernel.org/6.12/admin-guide/mm/concepts.html#page-cache)说明普通文件数据的缓存用途。Linux 0.11 的缓冲区实现应另按其源码理解。

## 2. 程序、进程与线程

以一个简单文本编辑器为例：磁盘上的可执行文件保存代码和初始数据，它是**程序**，此时没有正在执行的指令位置。启动它以后，操作系统建立地址空间、打开文件等资源，并创建执行流，形成**进程**。再次独立启动同一个程序，可以产生另一个进程；二者不因代码来源相同就共享所有可写数据。

**线程**是进程中的执行流。假设编辑器采用两个线程，一个处理界面，一个执行后台拼写检查：它们通常共享地址空间和已打开的文件，但各自保留指令位置、寄存器、栈及调度状态。因此共享文本数据需要同步；某个线程等待工作时，另一个线程仍可能推进。真实浏览器还可能采用多个进程，这里只用一个进程内的线程说明关系。

内核必须记住任务处于可运行还是等待状态、下次从哪里执行、关联哪些资源。教材常把这些记录抽象为 PCB（Process Control Block，进程控制块）和 TCB（Thread Control Block，线程控制块）。它们是描述职责的教学模型，各系统不必使用相同名称或把信息放在一张表中。Linux 0.11 的 `task_struct` 表示该版本的任务；不能把它直接套成所有系统的 PCB/TCB 布局，也不能据此推导现代线程实现。

并发允许多个活动在重叠时间区间推进，单核可通过交替实现；并行要求实际同时执行，例如多个 CPU 核。不能用“同时启动”区分二者，也不能因为进程很多就推导正在并行运行。

下面每列代表一个时间区间，切换开销省略；A、B 是两个任务：

```text
时间 →       t0—t1   t1—t2   t2—t3   t3—t4
单核 CPU 0     A       B       A       B     并发，未同时执行

双核 CPU 0     A       A       A       A
     CPU 1     B       B       B       B     两个任务并行执行
```

单核时两个任务都在这段时间内推进，但任一时刻只执行其中一个。双核时它们才可能在同一时刻执行；并发不必然意味着并行。

## 3. 特权模式与内核保护 {#_3-为什么需要内核保护}

如果任何应用都能修改页表、屏蔽中断或写任意设备，它就能破坏其他程序与系统状态。硬件提供特权模式和受控入口，内核据此管理操作权限。

进入内核态也不意味着可以不受规则约束地访问任意资源：页保护、体系结构限制、内核自身约束和错误处理仍然有效。用户指针仍需校验，不能因代码已进入内核就直接信任参数。

## 4. 历史是一条需求线，不是产品家谱

早期任务需要人工装入和衔接，**批处理**把作业成批组织起来，减少人工干预与作业之间的空档。程序等待 I/O 时 CPU 仍可能闲置，**多道程序**让多个程序驻留，使其他就绪程序能够利用这段时间。用户希望及时得到交互响应，**分时系统**通过较短的运行片段和调度，让多个用户或任务轮流获得服务。这些需求可以在同一个系统中并存。

UNIX、Linux、DOS、Windows 等有不同的历史和实现路线，不能从相似接口直接推导代码继承或内核机制相同。

历史背景用于理解需求的变化；具体系统之间的接口关系、代码继承和内核机制，需要分别结合源码与历史资料判断。学习本册时，重点放在每种机制解决的问题上。

## 本章小结

- 操作系统通过资源管理、抽象接口和保护，让多个程序能够有序共享计算机。
- 程序是静态文件，进程提供运行环境，线程携带具体执行状态。
- 并发强调一段时间内共同推进，并行强调同一时刻实际执行。
- 文件读取可能走缓存路径，也可能等待设备，相关组件根据条件协作。
