# 第一章 操作系统全景、历史与学习边界

> 阅读标签：通用原理 / 历史导读。

操作系统在硬件之上提供进程、虚拟地址、文件和通信等抽象，让程序通过统一接口使用计算机资源。多个程序同时运行时，它负责分配 CPU、内存和设备，隔离彼此的访问，并处理运行中的故障。本册从 Linux 0.11 的 CPU 与内存机制入手，再与其他教学系统和现代 Linux 对照。

## 1. CPU、内存与 I/O 的协作 {#_1-三条主线怎样连起来}

CPU 管理让多个执行流获得运行机会；内存管理让程序使用受保护的地址空间；I/O 与文件系统让程序访问设备和持久状态。同步把这些并发活动组织成正确的状态变化。

![应用、内核与硬件的职责](/assets/notes/operating-systems/os-overview.svg)

以读取文件并统计结果的程序为教学例子：程序先执行用户代码，再通过系统调用请求读取；数据可能来自缓存，也可能需要等待设备。等待期间可调度其他任务，数据就绪后再继续计算。因此，一次 read 涉及文件、内存、设备与调度，不只是一次函数调用。

## 2. 程序、进程与线程

程序是可执行代码与数据的静态描述，进程是运行中的资源与保护环境，线程是执行上下文。具体内核可以用不同结构表示它们，PCB、TCB 是教学抽象，不要求所有系统都使用相同名字和布局。

并发允许多个活动在重叠时间区间推进，单核可通过交替实现；并行要求实际同时执行，例如多个 CPU 核。不能用“同时启动”区分二者，也不能因为进程很多就推导正在并行运行。

## 3. 特权模式与内核保护 {#_3-为什么需要内核保护}

如果任何应用都能修改页表、屏蔽中断或写任意设备，它就能破坏其他程序与系统状态。硬件提供特权模式和受控入口，内核据此管理操作权限。

进入内核态也不意味着可以不受规则约束地访问任意资源：页保护、体系结构限制、内核自身约束和错误处理仍然有效。用户指针仍需校验，不能因代码已进入内核就直接信任参数。

## 4. 历史是一条需求线，不是产品家谱

批处理提高设备利用率，多道程序让等待 I/O 的时间可被其他任务利用，分时系统强调交互与共享。UNIX、Linux、DOS、Windows 等有不同的历史和实现路线，不能从相似接口直接推导代码继承或内核机制相同。

历史背景用于理解需求的变化；具体系统之间的接口关系、代码继承和内核机制，需要分别结合源码与历史资料判断。学习本册时，重点放在每种机制解决的问题上。
