# 第九章 HyperLogLog 与近似去重

HyperLogLog（HLL）估计去重后的基数，例如一天约有多少独立访客。它适合只要数量、不需要成员列表且能接受统计误差的场景。

## 1. 先区分数量与成员查询

| 需求                   | Set          | HyperLogLog      |
| ---------------------- | ------------ | ---------------- |
| 精确成员判断           | 可以         | 不提供           |
| 列出成员               | 可以         | 不提供           |
| 去重数量               | 精确集合基数 | 近似估计         |
| 合并多个集合的去重范围 | 集合操作     | 合并对应统计结构 |

HLL 不保存一份可重新取出的完整用户名单。因此不能用它判断“订单 42 是否处理过”，也不能从统计结果恢复所有原始事件。

## 2. 基本用法与返回

新增示例，未运行：

```redis
PFADD demo:uv:day-1 user-a user-b user-a
PFCOUNT demo:uv:day-1
PFMERGE demo:uv:period demo:uv:day-1 demo:uv:day-2
```

PFADD 的返回值表示内部统计结构是否发生变化，而不是本次精确新增了几位用户。同样，不能直接用 PFCOUNT 本次估计与上次结果的差值，作为精确新增数。

合并统计结构可以估计去重并集。两天各自 UV 直接相加则没有去掉跨天重复；两个 HLL 数字相减也不提供通用精确差集。[PFCOUNT](https://redis.io/docs/latest/commands/pfcount/)

## 3. 标准误差与输入统计口径 {#_3-误差怎样理解}

约 0.81% 按标准误差口径理解，用于描述基数估计的统计性质。单次估计偏差与成员误判概率属于不同概念，不能将它读成每次结果的绝对误差上限。

统计质量还依赖输入口径：同一用户是否采用稳定标识，机器人和匿名会话如何区分，重复事件与跨端用户怎样定义。算法正确也不能修复输入定义不一致。

## 4. 内存与删除边界

Redis HLL 有稀疏和稠密等表示，内存不能只用“极小”代替实际预算。稠密主体约 12 KiB 的常见说明，不包括键、对象和分配器等全部开销；大量时间分桶仍需总量核算。

不能像 Set 那样从 HLL 安全删除一个成员。需要可修正的统计时，应保留权威事件或按时间分桶后重新计算，不把 HLL 当成唯一原始数据源。

## 5. 对照精确基数验收估计结果 {#_5-如何验收}

对同一批样本分别计算精确去重结果和 HLL 估计值，在不同基数与分布下比较误差。同时记录采样时间、用户标识规则和是否经过合并，不能只挑选一个接近的结果来证明效果。

本章未运行统计实验，命令结果不会伪装成你环境的测量。适用于趋势报表的误差，未必适用于财务结算或唯一业务事件判定。
