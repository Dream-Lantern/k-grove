# 附录 B：贯穿案例与纸面练习

贯穿任务是：**打开文本文件 → 分块读取 → 并发统计 → 汇总 → 保存结果 → 观察延迟**。先选只读输入，输出只写入自己创建的临时目录；进程管理、线程分工、调度、同步、内存和文件持久化都围绕同一个任务讨论，不必开发复杂服务。

学习路径：基础做第 1、2 节；进阶做第 3～6 节；综合做第 8～11 节。各题均给出初始条件、参考过程和边界。下面状态与指标都是**纸面模型或教学预期**；本轮纯数值复核不等于真实系统性能测量。实际程序运行与待验证环境见[附录 A](/articles/os-version-references.html)。

## 1. 一次读取的状态图

**对应第 1、3、4、6、11 章；基础。** 目标是区分进入内核、缓存命中、阻塞、唤醒与调度。初始 A 正在运行，B 就绪；A 读取的普通文件数据尚未就绪，需要等待适用 I/O。任务：画出 A/B 的状态并标明何时才能继续处理本批文本。

| 时刻 | A                          | B              | 参考解释                            |
| ---- | -------------------------- | -------------- | ----------------------------------- |
| T0   | 用户态执行                 | 就绪           | A 发起 read，进入内核仍是同一个任务 |
| T1   | 处理中，发现需等数据       | 就绪           | 并非每次系统调用都走这个分支        |
| T2   | 等待                       | 获调度执行     | A 保存续接状态，实际更换执行任务    |
| T3   | 就绪                       | 可能仍运行     | 数据完成并唤醒 A；不保证立即抢占 B  |
| T4   | 获调度、完成内核路径并返回 | 依调度结果而定 | 检查 read 返回量，处理本批文本      |

预期：有效缓存命中可省去本次设备请求与相应等待，但 read 的用户缓冲等仍可能缺页。常见错误是把进入内核当作换进程，把设备完成当作 A 已经开始执行。本题只抽象成功路径，实际仍需处理短读、EOF、EINTR 等情况。[read(2)](https://man7.org/linux/man-pages/man2/read.2.html)

## 2. 地址手算

**对应第 13～15、17 章；基础。** 目标是严格分开段转换和分页。题 A/B 固定 x86 32 位非 PAE（Physical Address Extension，物理地址扩展）、4 KiB 页、普通两级分页、4 字节表项、非大页；段基址为 0，因此题中虚拟数值按线性地址拆分。任务是计算索引与物理地址，而非访问这些真实地址。

| 输入          | 参考计算                                       | 答案                               |
| ------------- | ---------------------------------------------- | ---------------------------------- |
| 0x2240        | 页号 `address>>12`；偏移 `address&0xFFF`       | 页号 2，偏移 0x240                 |
| 该页映到 PFN7 | `7×4096+0x240`                                 | 物理地址 0x7240                    |
| 0x00403210    | `address>>22`，`(address>>12)&0x3FF`，低 12 位 | PDE 索引 1、PTE 索引 3、偏移 0x210 |

PDE/PTE 分别为页目录项（Page Directory Entry）/页表项（Page Table Entry）。缺一张二级表只影响相应范围；不等于全部内存不存在。1024 项的二级表覆盖 4 MiB，目录和每张二级表各 4 KiB。

扩展计算：完整平坦单级表有 `2^20` 项，大小为 4 MiB；只映射 0x2000 所在一页时，两级表占 4+4=8 KiB；再映射 0x400000 所在一页，因属于另一个目录项，变为 4+2×4=12 KiB。均不含数据页和其他内核元数据；稠密两级表不一定比单级小。

题 C **另外固定 Linux 0.11 原版任务槽布局**，逻辑偏移仍为 0x2240，段基址为槽号×0x04000000：

| 槽号 | 段基址＋逻辑偏移＝线性地址   | 目录/二级索引/偏移 |
| ---- | ---------------------------- | ------------------ |
| 1    | 0x04000000+0x2240=0x04002240 | 16 / 2 / 0x240     |
| 2    | 0x08000000+0x2240=0x08002240 | 32 / 2 / 0x240     |

预期：同一逻辑偏移可落到不同线性范围，两者数据页仍可共享。常见错误是把槽号当 PID、把基址间隔当实际物理占用，或将题 A/B 的零段基址偷偷用于题 C。本题不模拟现代 x86-64 四/五级分页。

## 3. TLB 算例

**对应第 16、18 章；进阶。** 翻译后备缓冲（TLB，Translation Lookaside Buffer）缓存翻译。初始 t=1、m=100、n=2、h=0.9，分别表示查询成本、一次内存访问成本、页表层数和命中率。固定串行、无其他缓存/重叠/预取且**没有页故障**的教学模型。

任务：计算有效访问时间（EAT，Effective Access Time），再将 h 改为 0.95、0.99。

```text
命中：t+m=101
未命中但翻译有效：t+(n+1)m=301
EAT=h×101+(1-h)×301
h=0.90：121；h=0.95：111；h=0.99：103
```

单位是抽象时间；第 16 章为方便标了 ns，那里同样是人为设定而非实测纳秒，两处采用相同计算模型。n 次读页表之外还要读一次数据。

参考解释：TLB Miss 可能只需查有效页表，Page Fault（页故障）涉及不存在或权限等异常，二者不等价。修改 PTE 后缓存里可能仍有旧 PFN 或旧权限，所以要按架构和内核协议失效，并处理其他 CPU；仅改内存中的表项不保证所有访问立即采用新翻译。常见错误是把每次 Miss 成本都写成读盘，或把这条串行公式当现代处理器基准测试。

## 4. fork 与写时复制

**对应第 4、17、18 章；进阶。** 目标是区分映射、权限和物理内容。初始一个合法私有可写受管理页、内容 A，无其他适用引用；为与历史正文一致，采用已合法分配的 PFN1066/PFN1123，4 KiB 页，均在实际可用物理范围内。任务：画出四阶段 PTE 与引用计数。

| 阶段      | 父 PTE/内容   | 子 PTE/内容   | 适用引用数             |
| --------- | ------------- | ------------- | ---------------------- |
| fork 前   | 1066、RW=1、A | 无            | 1066=1                 |
| fork 后   | 1066、RW=0、A | 1066、RW=0、A | 1066=2                 |
| 子写 B 后 | 1066、RW=0、A | 1123、RW=1、B | 两页各 1               |
| 父再写 C  | 1066、RW=1、C | 1123、RW=1、B | 两页各 1，父不必再复制 |

以上 PTE 均有效，RW 是可写位。箭头是 `父/子 PTE→相应 PFN`；父子独立二级表与共享数据页是不同对象。原版 0.11 还共用页目录根，不能把“复制页表”理解为所有层都复制。

若子写前父先退出并释放其适用引用，剩余者写入可恢复权限而不必复制；显式 MAP_SHARED 则以共享更新语义为目标，不能套私有 COW 结论。真实现代页引用还包含更多内核关系，本题计数只表达限定模型。

历史例外：0.11 从任务 0 的 `from==0` 首次复制只遍历每轮 0xA0 项，低于 LOW_MEM 的页不走普通源写保护/引用递增分支。不能用这一特例否定普通 fork 私有空间语义，也不能把低内存 PFN42/99 当作本表的受管理页。该题是源码与状态推演，不是启动旧内核的记录。

## 5. 条件等待

**对应第 8～10 章；进阶。** 队列初始为空，消费者 C、生产者 P，队列谓词和修改均应由同一个互斥锁 M 保护。目标：定位错误检查/睡眠窗口，并用 POSIX 条件变量关闭它。

错误时间线：C 持 M 发现空 → C 解锁 → P 持 M 入队并通知、解锁 → C 重新持 M 却不重查，直接 wait。若此后不再生产/通知，C 可能一直等；条件变量不会替未来等待者储存一次通知。此例即便队列访问本身持锁，也仍存在协议错误。

| 正确步骤               | 状态与参考答案                                                    |
| ---------------------- | ----------------------------------------------------------------- |
| C 持锁                 | 用 `while (队列为空且未关闭)` 检查受保护谓词                      |
| C 调 pthread_cond_wait | 对互斥锁的释放与开始等待按接口原子衔接，不能拆成普通 unlock/sleep |
| P 持锁修改             | 入队，更新谓词并通知，随后按协议解锁                              |
| C 被唤醒               | 可能仍等 CPU、也可能等 M；不保证立即运行                          |
| wait 返回              | C 已重新获得 M，必须用 while 重查                                 |
| 多个消费者             | 另一消费者可能先取走唯一元素，或存在虚假唤醒；空则继续等          |

最小调用形态是 `pthread_mutex_lock → while 检查 → pthread_cond_wait → 处理 → pthread_mutex_unlock`，实际应检查返回码并设计关闭、错误和对象生命周期；完整可复现实验见[第九章](/articles/os-semaphores-conditions.html)。常见错误是用 if 替代 while，或把被唤醒等同资源必然归自己。

若改成不同线程未同步读写 C11 普通变量并发生数据竞争，则是未定义行为；不能把“错误交错可能丢更新”误写为该 C 程序全部合法结果。volatile 也不建立所需同步。[N1570 §5.1.2.4](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)

### 一个可核对的死锁题

初始 L1/L2 各只有一个独占实例；A 持 L1 请求 L2，B 持 L2 请求 L1，两者不会自行超时/释放。任务：写等待环与一个预防办法。

答案：A→L2→B→L1→A；在本题资源假设下，双方不能自行推进。所有路径统一按 L1→L2 获取，则等待边只能指向更高锁序，破除此锁集合的逆序环。它不保证公平，也不覆盖其他隐藏锁或协议死锁。资源不可抢占说的是所有权，不是 CPU 不能切换。安全状态/银行家向量计算可继续做[第十章](/articles/os-deadlocks.html)现成输入及模拟，本题不人为制造真实挂死。

## 6. 调度与资源

**对应第 7 章；进阶。** 为与正文一致，A/B/C 同在 0 到达，CPU 执行时间 8/4/2，单 CPU、无 I/O、上下文切换成本为 0、初始队列 A→B→C；FCFS 为先来先服务，SJF 为非抢占最短作业优先，RR 为时间片轮转且片长 2。

任务：画区间，算首次响应、周转、等待及平均值。响应=首次开始−到达；周转=完成−到达；本题无 I/O，所以等待=周转−CPU 时间。

```text
FCFS：A[0,8) → B[8,12) → C[12,14)
SJF ：C[0,2) → B[2,6) → A[6,14)
RR  ：A[0,2) → B[2,4) → C[4,6) → A[6,8)
      → B[8,10) → A[10,12) → A[12,14)
```

RR 最后两个时间片都运行 A，片边界不必切到另一任务。

| 算法 | 任务 | 响应 | 完成/周转 | 等待 |
| ---- | ---- | ---- | --------- | ---- |
| FCFS | A    | 0    | 8         | 0    |
| FCFS | B    | 8    | 12        | 8    |
| FCFS | C    | 12   | 14        | 12   |
| SJF  | A    | 6    | 14        | 6    |
| SJF  | B    | 2    | 6         | 2    |
| SJF  | C    | 0    | 2         | 0    |
| RR   | A    | 0    | 14        | 6    |
| RR   | B    | 2    | 10        | 6    |
| RR   | C    | 4    | 6         | 4    |

| 平均指标 | FCFS       | SJF       | RR         |
| -------- | ---------- | --------- | ---------- |
| 响应     | 20/3≈6.67  | 8/3≈2.67  | 6/3=2.00   |
| 周转     | 34/3≈11.33 | 22/3≈7.33 | 30/3=10.00 |
| 等待     | 20/3≈6.67  | 8/3≈2.67  | 16/3≈5.33  |

预期与正文一致。原先 A=8/B=2 的不同输入不再混用。真实任务等待 I/O 时离开就绪选择，时间片无限减小也会受开销限制；上述平均值不是现实调度器实测，也不把三算法等同 Linux 0.11 或现代公平调度。

## 8. 关键条件的综合练习 {#_8-复核后的边界练习}

**对应第 4、6、8、12、17 章；综合。** 使用贯穿案例的多个执行流、保存线程及历史对照。任务和参考答案一一对应：

| 问题                                       | 参考答案                                                                                           | 易错边界                                           |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 未同步普通变量更新为何不能只列交错？       | C11 数据竞争导致未定义行为，先依据标准排除该程序                                                   | 多运行几次不能证明合法结果全集                     |
| T2 持锁，T1 fork 后谁能释放继承状态？      | 子进程只有 T1；原持有者 T2 不在子进程中，不能假定锁自行恢复                                        | exec 前调用受异步信号安全限制；atfork 不是通用修复 |
| 0.11 三种调度位置？                        | 用户 CPL 下 counter 耗尽可调度；内核 CPL 耗尽不在该 do_timer 末尾调度；内核显式等待可调用 schedule | 不能外推现代 Linux 内核不可抢占                    |
| 槽 1/2 相同偏移为何不同线性地址？          | 段基址不同；PDE 为 16/32，PTE 索引同为 2，可指同一数据页                                           | 同索引不等于同一个表对象；根/二级/数据页要分清     |
| 修改映射→MS_SYNC→munmap/close 是否是事务？ | 同步与生命周期均不提供多字段业务原子性，close 和 munmap 的先后也不能代替完整持久化协议             | 无断电运行记录就不能宣称崩溃恢复通过               |

## 9. 页面置换练习

**对应第 19 章；综合。** 输入固定 `1,2,3,4,1,2,5,1,2,3,4,5`，初始空，分别 3/4 个可淘汰页框，无预取、无脏页成本；空槽从低编号填，OPT 下一次使用同样远时取低槽。任务：记录每一步访问、命中/缺页、淘汰和累计值，再比较总数。

| 策略              | 3 框缺页数 | 4 框缺页数 | 参考判断                                   |
| ----------------- | ---------- | ---------- | ------------------------------------------ |
| FIFO，先进先出    | 9          | 10         | 命中不更新装入顺序，出现 Belady 异常       |
| LRU，最近最少使用 | 10         | 8          | 命中更新近期访问历史                       |
| OPT，最优对照     | 7          | 6          | 依赖未来信息，不是可直接在线获得的预知能力 |

关键步骤：FIFO/3 框第 8、9 步访问 1/2 命中，累计仍为 7，但不改变进入顺序；第 10 步访问 3 淘汰 1，累计 8；第 11 步访问 4 淘汰 2，累计 9；最后 5 命中。全部六组状态和可运行断言见[第十九章完整图表与 Python](/articles/os-page-replacement-swap.html)。

验证命令：将该章代码保存为 `replacement.py`，运行 `python3 replacement.py`，对照每步输出及末尾断言。结果只属于给定模型，不能外推“多装内存会让现代 Linux 普遍更慢”。

## 10. 文件映射与保存练习

**对应第 11、12、20 章；综合。** 临时文件长 8192 字节，前八字节 ABCDEFGH；普通缓冲文件路径，分别建立可写私有/共享映射，不使用 DAX 或 Direct I/O，也不并发截断。任务：预测下面结果，并解释文件保存协议。

| 动作                                   | 教学预期与参考原因                                                         |
| -------------------------------------- | -------------------------------------------------------------------------- |
| read 读取文件前缀                      | 普通用户缓冲取得 ABCDEFGH；检查实际字节数                                  |
| MAP_PRIVATE 首字节写 X                 | 该私有映射看 XBCDEFGH，原文件仍 ABCDEFGH                                   |
| 解除私有，再建 MAP_SHARED 写 Y         | 普通文件读取可观察 YBCDEFGH，不需等到 msync 才“有可见性”                   |
| msync(MS_SYNC)                         | 检查返回，成功表示适用范围同步完成；不提供应用事务                         |
| fsync 文件/必要的目录                  | 按文件与命名发布协议处理；文件同步不自动保证目录项同步                     |
| 临时结果 fsync→rename→必要的目录 fsync | 同一文件系统内适用 rename 可原子替换名字；崩溃持久性仍有独立协议和设备边界 |

按[第二十章 C 实验](/articles/os-mmap-page-cache.html)保存代码后运行：

```bash
gcc -std=c11 -Wall -Wextra -Werror mmap-demo.c -o mmap-demo
./mmap-demo
```

程序创建自己的临时文件并清理，预期打印私有 X/原文件 A、共享 Y 和 MS_SYNC 成功后的 Y；该观察曾在附录 A 注明环境完成，但读者本次结果仍须独立记录。并发发布多个字段还需锁/原子协议，持久化事务还需日志等设计；不把一次正常读取或程序退出当作断电验证。

## 11. 性能问题的多假设分析

**对应第 19～21 章；综合。** 假设服务平均 CPU 不高、P99 升高，同时 Major Fault 或 memory PSI 发生变化。目标是写出可被反驳的解释，不寻找唯一预设答案。以下是合成场景，无实测故障日志。

| 候选解释                  | 安全观察                                                       | 支持证据与仍不确定的部分                                      |
| ------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------- |
| 关键串行线程/CPU 配额受限 | 线程区间占用、亲和性、schedstat 差值、正确 cgroup cpu.stat/max | 热点或节流与延迟同窗增长；仍需业务阶段证据                    |
| 冷文件访问或工作集受限    | Major/Minor 增量、文件范围、周期 vmstat、memory PSI            | 持续回收和停顿支持预算不足；一次 Major 增长也可能只是首次读取 |
| 下游、连接池或锁等待      | 线程状态、已有转储、队列、持有者和下游延迟                     | 同窗等待链可支持依赖瓶颈；futex 单点栈不证明死锁              |

最小只读入口如下，默认观察当前 Bash；替换为服务 PID 时先核对身份、启动时间和权限：

```bash
pid=$$
date -Is
ps -L -p "$pid" -o pid,tid,psr,stat,pcpu,comm
cat "/proc/$pid/status"
cat "/proc/$pid/cgroup"
vmstat 1 5
if [ -r /proc/pressure/memory ]; then
    cat /proc/pressure/memory
fi
findmnt -t cgroup2
```

在同一窗口记录业务吞吐/错误/P99，重复采集累计量取差值，并按[第二十一章](/articles/os-troubleshooting.html)确定命名空间、挂载根、控制器及祖先限制；不猜固定 cgroup 路径。ps pcpu 通常是生存期比例，不等于刚才一秒；vmstat 首条速率与周期行也要分开。PSI 不支持或不可读应记“缺证据”，不能写“压力为零”。

参考结论只到“哪些假设更有/更少支持”。可在隔离环境设计有限对照，保持请求量和统计口径一致；此处未执行真实负载、资源调整或故障注入。常见错误是拿不同时间点的指标拼因果、用整机均值排除单线程瓶颈，或因重启恢复就宣称根因已定位。
