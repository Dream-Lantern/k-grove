# 附录 B：贯穿案例与纸面练习

以下均为新增的合成练习，尚无运行记录。通过“打开文件、读取并统计、并行处理、保存结果”串联进程、同步、地址与 I/O，无需先安装旧内核，也能理解这些机制。

## 1. 一次读取的状态图

设任务 A 调用 read，缓冲数据尚未就绪，B 正在等待 CPU。先画出 A 从运行进入等待、B 获得调度、设备完成、A 被唤醒并再次获调度的顺序。参考解释：设备完成提供了继续执行的条件，A 还要等到真正获得 CPU 才能推进。

缓存中数据有效时，可以省去本次设备请求与相应等待路径。可以据此对照系统调用、进入内核与磁盘读取三个层次，标出它们各自发生的条件。

## 2. 地址手算

在 32 位非 PAE、4 KiB 页的模型中，取虚拟地址 0x2240：虚拟页号为 2，偏移为 0x240。若页框号为 7，得到物理地址 0x7240。

再取地址 0x00403210：目录索引为 1，页表索引为 3，偏移为 0x210。这里前提是普通 4 KiB 两级映射，不是大页或其他架构。尝试解释为什么缺少第二级表不等于该进程全部内存不存在。

## 3. TLB 算例

假定 t=1、m=100，n=2，h=0.9，且满足第 16 章列出的无其他缓存与缺页等简化条件：命中成本 101，未命中成本 301，平均为 0.9×101+0.1×301=121。

单位为抽象时间，不是实测纳秒。真实硬件为何可能不符合这组串行模型？改变页尺寸时除了命中率，还应考虑什么？

## 4. fork 与写时复制

父子私有映射初始指向同一物理数据页。画出子进程写入前后的映射、引用数和内容；如果父进程先退出，剩余持有者写入是否必然还复制一份？如果对象其实是显式共享映射，语义又有什么不同？

把“普通 fork API 语义”和“Linux 0.11 任务 0 首次 fork 特殊路径”分别列出，不能用后者覆盖前者。

## 5. 条件等待

队列初始为空。先推演“消费者检查空→生产者放入并通知→消费者才睡眠”的错误历史；再用持锁 while 检查与原子等待阻断该窗口。两名消费者同时被唤醒、只有一个元素时，第二名为什么还需重查？

练习不要求自行实现同步库。实际编程应使用平台支持的原语，并处理取消、异常、停止条件和对象生命周期。

## 6. 调度与资源

对 A=8、B=2、同一时刻到达且无 I/O 的单 CPU 模型，计算 FCFS 的两个顺序与 RR 首次响应。加入切换成本后，时间片能否无限缩小？若一个任务等待 I/O，它是否仍应参加当前就绪选择？

## 7. 后续实验的环境与验收 {#_7-后续实验如何安全开展}

开展实验前，先选择隔离环境、固定版本并建立可恢复快照，再逐项验证接口与结果。这里提供的是练习方案，尚未进行内核运行验收；运行结果需独立记录。

## 8. 关键条件的综合练习 {#_8-复核后的边界练习}

1. **data race**：抽象读写交错能得到丢失更新，但为什么不能枚举未同步C11普通变量程序的全部结果？用标准规则回答，不以多跑几次代替证明。
2. **多线程fork**：T2持锁，T1 fork后子进程只有T1。指出哪个持有者不再存在，以及fork到exec之间的调用限制。
3. **历史抢占**：分别列出0.11用户CPL耗尽counter、内核CPL耗尽counter、内核显式等待I/O的调度位置。
4. **地址层次**：偏移0x2240、槽1/2分别得到0x04002240和0x08002240。页目录项16/32、二级表项2和数据页的“共享/独立”各指哪种对象？
5. **持久化**：将修改映射、MS_SYNC返回、close(fd)、munmap放到时间线上，解释为何生命周期结束不等于业务原子事务或断电实验已通过。
