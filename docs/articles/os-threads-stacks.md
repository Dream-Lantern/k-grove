# 第五章 用户线程、内核调度实体与栈

> 阅读标签：通用线程模型 / 现代线程概念。

线程是可独立推进的执行上下文。多个线程通常共享所属进程的地址空间和资源，各自维护执行所需的栈、寄存器与线程局部状态。线程切换要保存当前执行位置和上下文，使它日后能够沿原来的调用链继续。

## 1. 调用栈保存各自的执行进度 {#_1-为什么不能随意共用一个调用栈}

函数调用会保存返回地址、局部变量及 ABI 所需状态。两个可任意交错的执行流若未经管理地复用同一段栈空间，一个流的压栈和返回就可能破坏另一个流的调用链。

![共享资源与独立上下文](/assets/notes/operating-systems/os-threads.svg)

独立栈使两条调用链可以分别推进，共享堆中的数据仍需同步。协程、分段栈和无栈状态机采用各自的执行状态管理方式，分析时应结合具体并发模型。[POSIX 线程概览](https://man7.org/linux/man-pages/man7/pthreads.7.html)

## 2. 用户级调度的 M:1 情况

若多个用户线程只由一个内核调度实体承载，一个阻塞系统调用可能使这个承载者等待，其他用户线程暂时没有执行机会。这是 M:1 模型的边界，不是所有用户级线程必然如此。

运行时可以使用非阻塞 I/O、事件循环，或用多个内核线程承载用户任务。M:N 的调度、同步与阻塞恢复更复杂，但说明“用户线程”与“无法利用多核”不能简单画等号。

## 3. 常见 1:1 模型

Linux NPTL 常见地将 pthread 映射到内核调度实体。线程共享进程地址空间与适用资源，一个线程阻塞不必让其他可运行线程全部停止；多核上也可能并行。

线程通常能够访问同一进程地址空间中的其他线程栈，因此“每线程有自己的栈”描述的是使用与生命周期分工，并不自动构成强隔离保护域。向其他线程传递栈上对象的地址时，还需保证对象不会因所属函数先返回而失效。

## 4. 内核线程与有用户线程的任务不同

“内核可调度的用户线程”通常拥有用户执行上下文和进入内核时所需的内核栈等结构；纯内核线程可能没有用户态地址空间与用户栈。不能统一写成“每个内核线程必然配一对用户栈、内核栈”。

TCB 保存哪些寄存器、线程局部存储怎样恢复、栈如何初始化，取决于 ABI、编译器和运行时。只在堆里分配一块内存，再把函数地址放上去，不足以构成可移植、正确的线程创建实现。

## 5. 教学切换示意

```text
保存当前执行流必须保留的寄存器与栈位置
选择下一条可运行执行流
恢复它的栈位置及约定的保存状态
从它先前保存的续接点继续
```

这段伪代码只展示保存与恢复的顺序。可运行的实现还要处理中断、信号、异常展开、向量寄存器、栈对齐和清理函数，具体要求取决于 ABI 与运行时。

学习时，先画出各执行流的调用链和栈，再分析共享资源，有助于区分“执行切换”与“资源隔离”。
