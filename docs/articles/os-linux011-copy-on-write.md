# 第十七章 Linux 0.11 段页结合与写时复制

> 阅读标签：Linux0.11段页结合与常规COW历史案例。

Linux 0.11 的段页结合是一种具体的历史布局，并非虚拟内存的唯一定义。原笔记将 64 MiB 线性区、LDT 和共享物理页联系起来，这条学习路线值得保留；但对“共用一套页表”和复制循环的解释需要修正。

## 1. 进程的逻辑视图与线性位置

原版 copy_mem 为任务设置与编号有关的代码/数据段基址，new_data_base 使用 nr×0x4000000，即 64 MiB 的历史间隔。由分段先形成线性地址，再进入分页。

该版本由同一个页目录组织整体线性空间，各任务经LDT段基址进入不同线性范围。目标范围可有独立的二级页表，而其中表项暂时指向共享数据物理页。**共享页目录、不同二级表、共享数据页是三种不同关系**，不能统称“共享页表”。

纸面算例：普通段偏移为0x2240，任务槽1的基址是0x04000000，线性地址为0x04002240；任务槽2的基址是0x08000000，线性地址为0x08002240。以32位非PAE、4KiB页模型拆分，目录索引分别为16与32，二级索引都为2，页内偏移为0x240。两条映射可以暂时指向同一物理页框。

nr是任务槽号，不是任意PID直接乘64MiB；64MiB是线性范围间隔，不是每个任务已经占用同样多物理RAM。现代每进程地址空间不必采用相同LDT布局。

## 2. copy_page_tables 复制什么？

它为目标范围分配相应页表，复制适用映射到同一物理页，调整写权限及引用计数。它并不是让父子进程永远指向同一套可变页表对象，也不是此时把所有用户数据页内容全部复制一遍。

外层循环推进页目录范围，内层循环处理一组表项；原笔记把 size 循环解释成多个进程数，并将两层作用拆错，不能当原样正确源码。[Linux 0.11 mm/memory.c 与 kernel/fork.c](https://www.kernel.org/pub/linux/kernel/Historic/old-versions/linux-0.11.tar.gz)

## 3. 写入时发生什么？

![私有逻辑与共享物理页](/assets/notes/operating-systems/os-cow.svg)

纸面推演：父子私有页初始都指向内容为 A 的物理页，并被写保护。子进程尝试改为 B，触发保护异常；内核确认是适用 COW 情况，必要时分配新页、复制内容、修改子映射，再恢复执行。父视图仍为 A。

如果某个物理页已由一方独占，适用实现可能直接恢复写权限，无需复制。因此，不能仅凭“发生写保护异常”就认定每次都会复制整块内存，也不能将真正只读代码页上的非法写入都视为 COW。

## 4. 任务 0 首次 fork 是特殊情况

原版 memory.c 与 init/main.c 对首次 fork 的低内存共享和栈使用有特殊说明，不能把这个特例抹掉，也不能用它证明一般父子进程的可变私有栈就是同一个共享对象。

本册采用“常规 fork 的 API 语义”和“0.11 特殊实现分支”分开叙述，避免现代 man-page 与早期内核注释相互覆盖。没有重新编译历史内核验证启动。

## 5. TLB 与回收必须配套

写保护、映射变更与引用释放都影响旧翻译是否仍有效。代码中的失效操作与引用计数参与保证，不能只复制两行赋值省略所有上下文。

练习时，可逐阶段画出“父映射、子映射、物理页、引用数”，再模拟一方退出、另一方写入。重点是理解何时共享、何时独立，以及哪一步需要恢复信息，而不是背诵某一行十六进制位运算。
