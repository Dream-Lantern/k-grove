# 第十三章 地址空间、重定位与分段

> 阅读标签：x86历史分段 / 现代地址空间对照。

虚拟地址使程序能够按自身的地址关系运行，物理内存由系统组织和共享。可以从 base+offset 的简化模型入手，再观察分段如何表达基址、界限与权限，最后与现代地址空间对照。教学模型、历史 x86 实现和现代平坦模型各有适用背景。

## 1. 编译、装载与运行期重定位

编译或链接阶段可以确定一部分地址关系；装载器可以调整相应位置；硬件地址翻译则让运行中的程序不直接绑定某个物理起点。真实格式还涉及相对寻址、动态链接等机制，不是所有地址只被修改一次。

因此“编译时只能固定位置”“载入后任何映射都不能修改”应限定为相应简化模型，而不是今天所有程序格式的共同限制。

## 2. 分段表达逻辑区域与访问权限 {#_2-分段要表达什么}

抽象分段把程序按代码、数据、栈等逻辑区域组织，可赋予基址、界限和权限。段号与偏移形成逻辑访问，再按规则得到目标地址。

[![x86 保护模式：分段与分页示例](/assets/notes/operating-systems/os-address.svg)](/assets/notes/operating-systems/os-address.svg)

在适用的 x86 保护模式中，段选择子联系 GDT/LDT 中的描述符；代码段、数据段和门有不同检查规则。现代 x86-64 普通代码常采用平坦模型，仍有特殊寄存器用途，不能照搬“每进程都用 LDT 管自己全部内存”。

## 3. 软件区域与硬件段并不相同

现代 Linux 的虚拟内存区域描述可记录范围、权限和后备对象，它不是历史 x86 段表的同义词。可执行文件的代码区域也不能直接等同一个硬件段描述符。

教学例子：两个进程都使用虚拟地址 0x400000，不必访问同一物理页。它们的地址空间映射可以不同；共享内存又可让不同虚拟地址映射同一物理页。保护与共享由明确映射建立。[Linux 内存概念](https://docs.kernel.org/6.6/admin-guide/mm/concepts.html)

## 4. 阅读分段汇编的前提 {#_4-原汇编片段的纠错}

阅读段内访问指令时，要分别确认段寄存器、偏移和传送方向。x86 常见段寄存器写作 ES，Intel 与 AT&T 语法的源、目的操作数顺序不同。

本章用“段选择信息 + 偏移 → 经检查形成地址”表达访问含义。将它写成可运行汇编，需要先确定目标位宽、执行模式、汇编器语法和指令语义。

## 5. 地址空间中的隔离与受控共享 {#_5-隔离不是每进程独占物理-ram}

进程可感知独立地址空间，同时共享库页、共享文件页或显式共享内存；内核通过权限和映射决定哪些访问允许。没有配置 swap，仍可拥有虚拟内存，不能把虚拟地址的存在归因于不断交换磁盘。

后续先分析可变大小分配与碎片，再介绍分页，最后讨论 Linux 0.11 特有的段页关系，避免将历史布局误认为通用定义。
